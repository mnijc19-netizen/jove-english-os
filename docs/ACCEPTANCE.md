# Acceptance contract

Completion is unproven until every gate below has current evidence. Record evidence and residual limits in STATUS.md; demo/mocked adapters cannot prove paid provider integration.

The final-upgrade gates in `FINAL_UPGRADE.md` are additive and mandatory. Older V1 acceptance is historical, not final completion. In particular, actual cloud sync/RLS/migration, autonomous authentic content delivery, real acoustic assessment, long-term recovery/plateau/reading, server secrets/budget/retention and desktop/mobile WebKit must be proven; provider stubs and Pixel emulation alone are insufficient.

1. CONFIG: inspect global/project/ancestor instructions, config/requirements/defaults/old role routing; preserve global settings and verify project Astra Ultra and actual active session metadata.
2. SPEC: durable product, architecture, learning science, decisions, acceptance and operating docs; full approved scope retained.
3. DOMAIN: tests prove deterministic plan changes with evidence, fatigue/interests/reviews/balance/completion; speaking always retained; separate modality FSRS cards; events rebuild skills; hints/self-report/text never impersonate independent spoken success.
4. DATA: tests prove schema migration, transactional/idempotent updates, reload persistence, schema-versioned secret-free backup/restore, corrupt/unknown/inconsistent import rejection without data loss, storage and recoverable audio policy.
5. CONTENT: audited built-ins and actual audio without key; pasted text, URL fallback, audio upload, web discovery, generated alternative; approved provenance/copyright/source labels.
6. ONBOARDING: fresh browser can complete goal, graded listening, vocabulary, speaking/skip, reading and preferences; actual responses shape initial model.
7. LISTEN: real audio playback, blind first, response before reveal, meaning/key-details check, English/Chinese reveal, unknown vs listening-gap classification, sentence repeat/slow/normal, shadow/retell and persisted evidence.
8. SPEAK: four modes and all named missions, recorder permission states, real local blob, editable STT, streaming conversation, end feedback 1–3 issues, prompted retry, full-sentence repair, same-day/delayed transfer scheduling. Error/cancel/reload retain input.
9. REVIEW: six modalities accessible, production recorded or explicitly text-only, revealed answer cannot grant independent mastery, FSRS due changes and separate skill updates.
10. PROGRESS: honest evidence counts/confidence, first-pass listening/latency/duration/Chinese fallback/chunk states/error recurrence, weekly trends, recurring five-part 14-day listening/retell/conversation/real-life mission/reading assessment with stable rubric and varied prompts. Historical four-part records must not acquire invented reading evidence.
11. PROVIDER: dynamic capability models, key test/remove, LLM JSON validation, streaming, STT/TTS contracts, timeout/retry/cancel, missing-model fallback, error normalization, per-purpose usage and budget, generated audio cache. Contract tests + live public catalog; paid smoke only with legitimate available key.
12. SECURITY: no real keys in Git/build/export/log/tests; content escaped; no arbitrary tools, settings mutation or raw external HTML; trusted HTTP(S) URL handling; minimal context; no telemetry; dependency and secret scan.
13. UX: visually inspect Today/Onboarding/Listen/Learn/Speak/Review/Library/Progress/Settings on desktop/mobile and light/dark; no overflow/truncation; loading/empty/error/offline states; keyboard/focus/reduced-motion/contrast/touch labels.
14. PWA: install manifest/icons/scoped SW, offline shell and existing review/material/audio, deliberate update, storage persistence status; no API authentication cache; deep-link hash reload/subpath assets.
15. REVIEWER: independent architecture/security/product/learning/AI/data/PWA/UX/a11y/performance/test/claims review; fix P0/P1 and every core-loop P2; recheck.
16. LOCAL: clean npm install, lint, typecheck, meaningful unit/integration, desktop/mobile Playwright and production build all pass.
17. RELEASE: correct Git author, commit/push, automatic Actions build/deploy, successful Pages status tied to exact commit, source visibility preserved, operational README.
18. PRODUCTION: actual fresh browser on public URL tests onboarding/demo/listen/review/settings/reload/routes/theme/mobile/persistence/PWA/no-key/API-error and no unexpected console errors. Live AI smoke separately qualified if no key exists.
19. DELIVERY: directly usable production URL, brief capabilities and first-use steps, truthful test status and any real limitation. Goal complete only after above evidence; human key/login issues cannot conceal unrelated unfinished work.
