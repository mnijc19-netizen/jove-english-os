## Browser component handoff

`PronunciationPractice.vue` accepts `reference: { id, text, audioUrl, audioSha256, voiceReview, revokedAt? } | null`, `savedAudioId?`, `savedReferenceId?`, `pendingAttempt?: { attemptId, recordingId, referenceId }`, `persistAttempt?: (attempt) => Promise<void>`, `recoveredResults?` and `disabled?`. Both pages supply the awaited persistence callback. Restored audio requires its saved reference association through `savedReferenceId` or matching `pendingAttempt`; bare IDs are recovery-only. Null/unknown/revoked review disables new playback/capture/assessment, while same-owner historical results remain readable. IDs are 1–100 ASCII letters/digits/underscore/hyphen; reference text is at most 2,048 UTF-8 bytes. Prop changes cannot rebind an earlier recording to a new reference. `audioUrl` is review metadata only, never a browser media URL or server fetch target; new playback requires authenticated retrieval and actual-byte SHA verification.

Events for the parent page/store owner:

- `recorded({ audioId, duration, referenceId })`: forward of Recorder's **existing event name**, adding the reference association at capture/save time. Persist both IDs and pass them back as `savedAudioId` + `savedReferenceId` after reload; never derive this association later from whatever reference is then visible. The component independently verifies `db.audio.get(audioId)` before conversion. It performs no database writes/deletes.
- `pending({ attemptId, recordingId, referenceId })`: notification only. The component separately awaits `persistAttempt` before upload; Vue events do not await listeners. Retry uses the same ID. A failed/uncertain dispatch requires the explicit “New service attempt · may be billed again” action to create another ID; no implicit paid replay.
- `evaluated({ ok: true, assessmentId, assessment, usage })`: `assessmentId` is the server-persisted evidence identifier, never invented in the browser. Main may persist a prompted-practice event, associate it with the recording, and schedule full-sentence repair/delayed transfer. Client-provided scores alone must never be trusted by the backend.
- `active(boolean)`: synchronous recording/conversion/request activity for parent navigation/mode guards. Cancellation and teardown prevent stale evaluation emission; original recordings remain in the existing recovery/database system.

The component displays 0–3 supported cues, unknown prosody and two distinct recordings for A/B comparison. `speech/practice.ts` persists minimal history associations, the pending reference text and an event outbox in dedicated existing-Dexie sessions. On reload it retrieves both server results without audio upload. Revoking a reference blocks new assessment but not historical owner-only recovery. `Recorder` and `SavedRecording` remain reused; STT text is never consumed as acoustic evidence.

`src/speech/client.ts` uses the existing `cloudClient` and authenticated `functions.invoke('speech-assess', { method: 'POST', body: FormData, headers: { Authorization: sessionJWT }, signal })`. This resolves to `/functions/v1/speech-assess`. FormData contains **only** `attemptId`, `recordingId`, `referenceId`, `audioWav` (PCM WAV file). It does not send reference text, provider credentials, quality facts or prosody configuration. The client requires a signed-in session, supports cancellation and a 75-second total deadline, and does not retry implicitly. The [official Functions API options](https://github.com/supabase/supabase-js/blob/master/packages/core/functions-js/src/types.ts) and installed implementation were checked for FormData, explicit authorization, signal and non-2xx response behavior.

The function's successful JSON must be `AssessmentResult` plus a **top-level `assessmentId`**, include the raw allowlisted Azure evidence, reference hash and exact request associations. The browser checks those associations, hashes the displayed reference text, and regenerates cues from raw provider fields rather than trusting supplied cue text. Non-2xx structured failure results can include the same `usage`; arbitrary error messages are discarded. HTTP 401 requests sign-in; HTTP 402 or structured `BUDGET`/`BUDGET_EXCEEDED` reports allowance unavailability. Missing configuration/session/review/evidence cannot emit `evaluated`.

### Preparing an actual reviewed reference artifact (operator contract, not an approval)

1. Keep a candidate outside `pronunciation_references` until a real accountable reviewer has listened to the exact short audio and confirmed rights, exact transcript, a single clear speaker, natural stress/rhythm, GA suitability, and no clipping/intrusive noise. Keep source and rights evidence, reviewer identity/time and review ID. A provider locale, model estimate, automatic clip gate or successful decoder does not establish these facts. No candidate/fixture may be inserted with invented `true` facts.
2. Freeze the exact reviewed WAV or MP3 (at most 2,000,000 bytes; a coherent short sentence suitable for the existing <=30-second learner attempt). Compute SHA-256 from the file's actual bytes. Do not hash a URL or text, transcode afterward, replace a reviewed file in place, or count a container signature as a quality review.
3. An authorized server/operator stores those exact bytes in the existing **private** `jove-content-audio` bucket at `references/{ownerId}/{referenceId}/{lowercaseSha256}`. Use a new reference ID for changed audio/text/review and do not upsert over a reviewed object. Download/read back the stored bytes and independently confirm size/SHA before connecting the approved review row. The browser has no general bucket read or arbitrary signing permission. No new bucket policy, migration or production write was performed by this patch.
4. Only after the real review and immutable-object readback succeed, the trusted operator may insert the matching owner-isolated 005 row. `audio_sha256` must be that object's SHA. `audio_url` remains an HTTPS review/source artifact locator required by the existing schema; it is **not followed** by the playback endpoint. The server derives the private object path from authenticated owner + reviewed ID + hash, never from this locator. For Listen, set `material_id` to the exact lesson ID; Speak can use the available reviewed pool. Rights/source evidence and all reviewer facts must describe the same artifact, not a nearby episode or another synthetic voice.
5. Authenticate as the normal owner and request `references`, then `reference-audio` by ID. Verify returned byte size/SHA against the frozen artifact and confirm native playback from a `blob:` URL with the production `media-src 'self' blob:` policy unchanged. Check another owner cannot read/sign it, bad hashes and withdrawn rows return no bytes, failure offers retry without deleting recordings, and revocation preserves the owner's historical A/B recovery. These deployment/storage checks still require the real dedicated backend and are not established by transport fixtures.

Internal signing uses `admin.storage.from('jove-content-audio').createSignedUrl(path, 60)`. The returned capability stays server-side. Its origin must exactly equal configured `SUPABASE_URL` and its path must exactly equal `/storage/v1/object/sign/jove-content-audio/references/{ownerId}/{referenceId}/{sha}`; only a token query is accepted, redirects are rejected, credentials are not forwarded, and stream bytes/time are bounded. ## Request and audio constraints

The verified [Microsoft short-audio REST contract](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-speech-to-text-short) specifies pronunciation assessment audio up to 30 seconds, 16 kHz mono PCM WAV, Base64 JSON assessment headers and final responses. This adapter targets the resource endpoint `/stt/speech/recognition/conversation/cognitiveservices/v1` with `language=en-US&format=detailed`, server subscription header, `HundredMark`, `Phoneme`, `Comprehensive`, miscue enabled and optional prosody. Redirects are rejected.

Application limits are deliberately stricter: 0.25–30 seconds; canonical 44-byte RIFF/WAVE PCM16 header; maximum 960,044 bytes; 2,048 UTF-8 reference bytes; nonempty plain text without markup/control characters; identifiers of 1–100 ASCII letters/digits/underscore/hyphen. Header/sample count/byte rate/data length are checked from the actual bytes, independently of uploaded MIME or claimed duration. Noncanonical WAV chunks and compressed WebM/MP4 are rejected at this boundary. The 0.25-second lower bound and reference limit are product/resource choices, not published Azure limits. All-zero PCM is rejected locally; other noise/silence is evaluated by the provider, never used to infer phoneme scores.

Browser flow: save the original recording Blob and local draft first; call `recordingToAssessmentWav(blob, signal)`; send the resulting PCM WAV to the authenticated function. Web Audio decodes the browser-supported container and renders mono at 16 kHz. `encodeAssessmentWav(samples)` only encodes already-rendered 16 kHz samples; it never relabels compressed bytes or performs naive decimation. Conversion is limited to 10 MiB compressed input and 30 seconds decoded duration, without clipping/truncating long user recordings. Choose a coherent short practice sentence rather than silently trimming a conversation. Original audio is untouched. Web Audio cannot interrupt decoding/rendering mid-operation; cancellation prevents delivering/submitting the result at the next checkpoint. Decoder support and resource behavior must still be checked on real WebKit/browser audio.

Default timeout is 20 seconds per attempt, configurable from 100 ms to 30 seconds, covering credential loading, network and response body. Response JSON is streamed with a 1 MiB bound. Aborts cover fetch, stalled bodies and retry delays; late credentials cannot trigger a request after timeout. Default retries are zero. An explicit `maxRetries: 1` permits one additional attempt for HTTP 429/503 only, with 250–5,000 ms backoff and respect for `Retry-After`; a longer backoff returns control instead of retrying early. Network failures/timeouts are not automatically replayed because submission/billing may already have occurred. Original blobs/drafts stay available for owner retry, skip or configuration repair.

## Supported evidence and honest feedback

`parseAzureAssessment` accepts both the official flattened REST response and nested SDK `PronunciationAssessment` JSON. It rejects invalid types/ranges, dangerous keys/accessors/prototypes, oversized structures, unsuccessful/no-speech responses, inconsistent duplicate scores, missing recognition confidence and first-hypothesis recognition confidence below 0.5. Per-word zero confidence placeholders in the official REST example do not invalidate a good utterance. The 0.5 gate is an uncalibrated product choice, not an estimate of acoustic measurement certainty. The best-scoring alternative is never selected to evade it.

`normalizeAzureAssessment` carries provider identity, immutable recording/attempt association, reference ID and SHA-256, en-US target, request conditions and an allowlisted copy of the exact provider fields used. Score values remain provider 0–100 values. No overall, phoneme, syllable, fluency or prosody score is computed from transcription/LLM output. A transcript, completeness or overall score alone is insufficient. Missing dimensions are null/empty. Omitted words retain alignment flags but no invented sound measurements; omission-only results cannot establish acoustic evidence. Offsets are converted from 100 ns ticks to milliseconds and bounded against the submitted recording.

The provider excerpt deliberately strips unknown fields, alternative hypotheses, unused nested feedback, SNR and candidate phoneme alternatives. `raw` means retained provider values with original paths, **not** an unrestricted response dump. This prevents arbitrary metadata/credentials from propagating. Existing error type flags, word/syllable/phoneme accuracy and aggregate fluency/prosody are sufficient for the implemented cues; no pitch/stress label is inferred from STT, a score or discarded confidence fields.

`selectPriorityIssues` selects up to three targets, one per word plus aggregate rhythm cues where supported. Scores below 70 guide cue selection only, not mastery. Each issue retains its raw provider path and value. If no supported issue exists it returns zero, rather than inventing a minimum correction. Practice is: approved reference → listen/read → saved recording → assessment → 1–3 supported cues → full-sentence retry → A/B listening. `compareAcousticAttempts` requires two distinct attempt/recording IDs, identical reference ID/hash, target, method and prosody settings. Deltas include only dimensions observed on both attempts; they do not label improvement, transfer or intelligibility. Microphone/noise/provider revisions remain comparison confounders. Immediate prompted repair stays separate from delayed unfamiliar-context evidence and FSRS modalities.

Microsoft's [assessment capabilities](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-pronunciation-assessment) document syllable groups for en-US with IPA/SAPI and prosody for en-US; SDK prosody requires 1.35.0+. Preserve the returned alphabet labels unchanged. REST requests use documented `Granularity=Phoneme`; this adapter does not promise that every response includes syllables or use undocumented alphabet switches. Missing requested prosody remains unknown. Longer/unscripted work needs a separately validated SDK pathway; SDK continuous mode has different miscue behavior. Locale support is never evidence that a particular reference voice passed review.

## General American reference voice policy

The stable production speaking target is General American/en-US. Wider listening accents are separate transfer input. `referenceVoiceEligible(review)` fails closed unless an identifiable review confirms rights, transcript agreement, clear single speaker, natural stress/rhythm, General American suitability and absence of clipping/intrusive noise. Facts may not be replaced with a voice-name guess or an automated provider score. A reviewed human reference is preferred. Reviewed synthetic speech is an explicitly labeled practice bridge; it does not become authentic primary listening or a certified human voice. Keep the same reviewed reference for retries; include unfamiliar human speakers in separate transfer work. Eligibility is consumed by the content/function owner before selecting a reference; the adapter cannot certify these facts from waveform/locale alone. Provider feedback never demands accent elimination or guarantees native-like speech or human-listener intelligibility.

Mapping the enhanced meter to prosody follows the Azure price-page feature table. An extra submission may incur the same charge again. This is arithmetic from retail evidence, not a measured bill. Do not use batch STT prices for pronunciation assessment.

`SpeechUsage` records separate `azure.speech.pronunciation` and (when requested) `azure.speech.prosody` entries on success **and** failure: requests attempted, submitted audio seconds, conservative whole-second estimated billing quantity, actual cost null, and not-submitted/unknown billing status. Prosody may be requested/billed even if evidence is absent. Usage here does not include LLM/STT/TTS from other services or storage/egress. Count distinct service meters; do not sum the duplicated audio seconds as learner speaking duration. The server must reserve budget for all permitted attempts, persist failed-call usage, and reconcile actual costs against provider billing. Authenticated idempotency for repeated attempt IDs, response caching, daily/week/month aggregation and quotas belong to the function/data owner. This module intentionally performs no invisible shared-state or retry caching.

Suitable peer: [Speechace plans](https://www.speechace.com/api-plans/) currently list Basic $40/month (5,000 15-second units, $0.008/additional unit, max 30 seconds), Pro $80/month (10,000 units, same overage, max 45 seconds, adds fluency/stress/intonation), and Premium $125/month (10,000 units, $0.0125 overage, max two minutes, spontaneous features). Its [score-text API](https://api-docs.speechace.com/api-reference/score-text-pronunciation) accepts en-us and uploaded audio. It is a plausible second dedicated acoustic provider, with different schema/usage/minimum spend. No peer adapter, validation of marketing calibration claims, account or purchase is included. Azure remains the implemented choice for bounded personal use and existing server fetch compatibility.
