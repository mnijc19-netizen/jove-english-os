# Architecture

Approved multilingual direction (2026-09-13): display brand Jove Language OS; keep the existing repository, Pages base/hash routes, PWA scope and database identities. Reuse the engine and infrastructure, not one blended learner state. Language-specific profile/evidence/cards/materials/plans/AI context and sync/backup migrations precede an enabled Japanese entry. Preserve the working English runtime throughout. See the ordered gates in `FINAL_UPGRADE.md`; this is an architecture requirement, not a claim that language isolation already exists.

Implementation contract (September20): keep the legacy English IndexedDB `jove-english-os` and its record IDs/wire format unchanged. A Japanese workspace uses `jove-english-os-ja`, the same database class and merge engine, with an immutable `ja` binding checked before opening. This partitions profiles, evidence, FSRS, drafts and projections without adding a filter to every learning query. No live mutable database pointer: a future language switch must save/cancel current work before remount/reload. Accounts remain shared, not a second login/site.

The English profile's dailyMinutes remains the shared account time preference, avoiding new fields that old English clients would reject. `readLanguageDay` combines only same-owner snapshots; `allocateLanguageDay` subtracts completion once, reserves ongoing work, and supplies per-language caps without changing history or card schedules. Old/offline clients cannot be made globally real-time: after reconciling already completed excess, stop adding required work rather than deleting it or claiming elapsed-time enforcement. English-only behavior stays unchanged when no Japanese learning space is enabled. `createLearningRepository(database)` binds writes, FSRS, repairs and backups to one immutable space; existing English imports retain their default binding.

`createJapaneseSpace` keeps a background database/CloudState separate from page-owned handles, reusing the same authenticated client and shared sign-out. Admission must match BOTH the English store's accepted principal and its persisted owner before Japanese binding/upload; the guard runs inside each immutable auth access, not just after a sync. An initialization epoch fences late continuations during sign-out/stop. Opening English only enumerates existing database names: do not use a dynamic-open absence probe (`Dexie.exists`) concurrently with first creation, because that implementation deletes its empty probe database. Per-language pending/error/recording states remain separate; English `Synced` is not Japanese acceptance. Remote refresh may update Today but never silently replace a visible answer; draft/repetition guards retain conflict recovery.

Keep the English sync table/RPC untouched for old clients; introduce a separate owner-RLS language stream for Japanese and a language-bound remote. Reject a journal/remote mismatch before capture or upload. Separate cursors/snapshots prevent old or offline English clients from importing/deleting Japanese evidence. Japanese backups require an explicit version3/language envelope; old unlabelled version2 backups remain English and cross-language restore is rejected before mutation. Japanese recordings use a separate owner-RLS manifest, canonical `owner/ja/id-hash` paths in the existing private bucket, and a retention RPC fenced by the Japanese metadata frontier plus the shared account policy. Noncanonical/encoded traversal paths fail before network access; migration constraints enforce safe paths server-side. English manifest/path/RPC contracts remain unchanged. Do not enable Japanese UI until recording ownership/retention, shared daily-time allocation, AI language context, appropriate curriculum and safe switching are wired and accepted. The data foundation alone is not a usable Japanese product.

Settings pins backup/restore/cache actions to the selected immutable language context before asynchronous work. File reading can be cancelled; changing language clears the pending file, while its filename cannot override the validated language envelope. Restore uses that space's protected local-change transaction, preserving newer work, original audio and sync identity/history. Merely opening Settings never creates Japanese. JSON backups still omit audio files: restored Japanese drafts retain text and first-answer locks, mark missing originals and return unfinished comparison work to recording when needed. A missing oral original cannot earn a longer interval from an easy self-rating. Local storage estimates show both languages; the existing recorder limit remains per-workspace, not an enforced account-wide aggregate quota.

AI adapters also bind their language/database at construction. Japanese requests carry a validated `learningLanguage: ja`; absent language retains the original English request hash/wire shape. Receipts, recovery identities and usage stay in that language's database. Japanese authenticated access checks both its owner and the English persisted owner, with the existing auth fence guarding asynchronous acceptance. The server includes language in the request fingerprint and reserves both languages against the same account ledger. Advanced BYOK reads the same browser key/settings and combines same-owner local language costs for its estimated daily guard; this is not a hard concurrent or cross-device billing ceiling.

Japanese tutoring uses Chinese explanations, natural Japanese context/register and Japanese segmentation, not English whitespace boundaries. After independent recording, the optional coach saves a checked text response before requesting feedback, retains a separate unverified transcription candidate, shows one hint before revealing a model rewrite, and keeps feedback tied to the submitted answer. Coaching creates no mastery/FSRS/acoustic events. Its draft belongs to the practice and closes with it. Transcription accepts only a saved original attached to that practice. Japanese STT explicitly sends `language: ja`; server defaults to Nova-3, whose Japanese support is documented. Japanese synthesis cannot borrow the English voice: it needs explicit server model/voice settings, a Japanese locale and a matching current catalog voice/verified price unit. It is not enabled or voice-quality accepted by this code contract.

API references checked September20: [OpenRouter STT parameters](https://openrouter.ai/docs/guides/overview/multimodal/stt), [Deepgram model/language support](https://developers.deepgram.com/docs/models-languages-overview), [OpenRouter supplemental TTS](https://openrouter.ai/docs/guides/overview/multimodal/tts). These establish request capability, not live owner-provider success or standard-accent certification.

September13 delivery amendment: curated external lesson metadata uses the existing Material/Listen/planner/session/sync architecture. Publisher media opens externally; the app stores original learning prompts and learner work, not copied publisher audio or transcripts. Normal practice no longer invokes automatic acoustic assessment. See `FINAL_UPGRADE.md` for current scope and partial-release boundaries.

Vue 3/TypeScript/Vite SPA, hash-history Vue Router, Pinia UI state, Dexie IndexedDB persistence, Zod validation, mature ts-fsrs scheduling, Vitest integration/unit tests and Playwright browser tests. CSS variables express the small design system without a second styling dependency. GitHub Actions publishes Vite dist to GitHub Pages at `/jove-english-os/`; PWA scope/start URL share that base.

`src/domain/types.ts` defines shared serializable entities. `src/domain/engine.ts` computes evidence aggregation, modality-specific review scheduling and deterministic plans. `src/db/` provides migration/bootstrap, atomic learning updates and backup. `src/ai/` defines provider contracts, schemas and OpenRouter implementation. `src/audio/` handles capture, PCM conversion, replay and speech. `src/content/` holds reviewed demo material and import helpers. `src/stores/` coordinates persistent state for Vue. `src/pages/` owns task flows; components provide reusable accessible controls.

All timestamps in persisted domain data are epoch milliseconds, except mature FSRS Card fields which are restored to Date instances at the boundary. Events have unique IDs and measured vs self-report vs AI vs text evidence provenance. Store events and their projections atomically. Prompts and model output never update settings or execute HTML. Keys live in a separate secrets table, are read only immediately around first-party provider requests and are never serialized in backups. Do not cache authenticated API traffic in the SW.

Use persisted learning-session drafts and conversation history to survive reload/errors. Capture audio before network calls. Provider failures preserve recordings and text, expose retry/cancel/skip/settings routes. Audio blobs have metadata for retention; delete generated cache only by policy and never discard unprocessed user recordings silently.

Content has source kind, provenance, approval, transcript, sentence structure, comprehension keys, chunks and synthetic/real audio labeling. Retain approved excerpts/user inputs, not mirrored paid libraries. Imported text renders with Vue escaping, URLs accept only HTTP(S), no executable DOM.

The deterministic planner balances weaknesses/due work/new input/fluency with minimum speaking and strain-aware duration. AI chooses phrasing, explanations and context variants within task constraints. Evidence scores express estimates with counts/confidence, not calibrated proficiency or phoneme measurements.

Verify deployment exact commit + successful Actions + public URL + fresh-browser journey. Existing visibility cannot be changed without owner authorization. Never add runtime secrets to Actions or static builds.

## Final-upgrade architecture boundary

Retain this SPA/Dexie/Pages architecture. Add a dedicated Supabase backend (never reuse another project's backend): Auth, append-only RLS-owned sync operations/events, private Storage, authenticated AI/Speech functions and scheduled content processing. The browser retains local learning and an offline journal; upload/download/merge rebuild derived evidence instead of replacing a whole database. Server-only production keys supersede the browser-only key rule for normal operation. Public frontend configuration may contain only project URL and publishable key. Entity/draft conflicts and audio retention must be specified/tested before production. Full requirement map: `FINAL_UPGRADE.md`.
